# WT-7. CargoFlow API на PostgreSQL и Entity Framework Core

Учебный проект по дисциплине «Web-технологии»: REST API для учёта грузов на складе,
перенесённый из **WT-6** с хранения в памяти на **PostgreSQL** через
**Entity Framework Core** (подход Code First, миграции).

Предметная область и сущность `Cargo` не менялись: это тот же домен
«Склад и логистика», который использовался в WT-4 (MVC), WT-5 (Razor Pages)
и WT-6 (Minimal API). Контракт REST API также сохранён, поэтому новый проект
является прямым продолжением лабораторной работы № 6.

## Что изменилось по сравнению с WT-6

| Было в WT-6 | Стало в WT-7 |
| --- | --- |
| `List<Cargo>` в `Data/CargoStore.cs` | `DbSet<Cargo>` в `AppDbContext` |
| Данные в памяти процесса | PostgreSQL |
| Данные терялись после перезапуска | Данные сохраняются в базе |
| Ручное назначение `Id` | `GENERATED BY DEFAULT AS IDENTITY` |
| Нет схемы БД | Миграции EF Core |
| Нет начальных данных в БД | `HasData` + миграция `SeedCargoes` |
| Нет истории изменений схемы | `__EFMigrationsHistory` |

`Data/CargoStore.cs` удалён. Все операции чтения и записи выполняются через
`AppDbContext`.

## Предметная область

**Склад и логистика.** Основная сущность — `Cargo` (груз на складе).

| Свойство | Тип | Назначение |
| --- | --- | --- |
| `Id` | `int` | Первичный ключ, генерируется PostgreSQL |
| `Name` | `string` | Название груза |
| `Category` | `string` | Категория |
| `Quantity` | `int` | Количество единиц |
| `Location` | `string` | Место хранения на складе |
| `Weight` | `decimal(18,3)` | Вес одной единицы, кг |
| `Description` | `string` | Описание груза |
| `IsAvailable` | `bool` | Признак наличия на складе |
| `CreatedAt` | `DateTime` | Дата добавления в БД (UTC) |
| `Supplier` | `string` | Поставщик груза |
| `TotalWeight` | `decimal` | Вычисляется в модели, `[NotMapped]` |
| `Status` | `string` | Вычисляется в модели, `[NotMapped]` |

Свойства `TotalWeight` и `Status` не хранятся в PostgreSQL: они помечены
атрибутом `[NotMapped]` и вычисляются при сериализации JSON.

## Entity Framework Core

Установленные пакеты:

```bash
dotnet add package Npgsql.EntityFrameworkCore.PostgreSQL --version 9.0.4
dotnet add package Microsoft.EntityFrameworkCore.Design --version 9.0.11
dotnet tool install --global dotnet-ef --version 9.0.11
```

`AppDbContext`:

```csharp
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options)
    {
    }

    public DbSet<Cargo> Cargoes => Set<Cargo>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // ограничения длины, precision для decimal, индексы и HasData
    }
}
```

Регистрация в `Program.cs`:

```csharp
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseNpgsql(connectionString));
```

При запуске приложение автоматически применяет миграции:

```csharp
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    db.Database.Migrate();
}
```

`EnsureCreated()` не используется: структура базы создаётся только миграциями.

## Миграции

Созданы четыре миграции, чтобы показать полный цикл Code First:

| Миграция | Что делает |
| --- | --- |
| `InitialCreate` | Создаёт таблицу `Cargoes`, индексы и первичный ключ |
| `AddCreatedAt` | Добавляет столбец `CreatedAt` и индекс по дате |
| `SeedCargoes` | Добавляет шесть начальных грузов через `HasData` |
| `AddSupplier` | Добавляет столбец `Supplier` и заполняет его у начальных записей |

Команды:

```bash
dotnet ef migrations add InitialCreate
dotnet ef migrations add AddCreatedAt
dotnet ef migrations add SeedCargoes
dotnet ef migrations add AddSupplier

dotnet ef migrations list
dotnet ef database update
```

История применённых миграций хранится в таблице `__EFMigrationsHistory`.

## Строка подключения

Для локального запуска в `appsettings.json` используется демонстрационная строка:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=wt_lab7;Username=postgres;Password=postgres"
  }
}
```

Это **не настоящий секрет**: пароль `postgres` предназначен только для локального
учебного контейнера. В рабочем проекте настоящий пароль должен передаваться
через переменные окружения или пользовательские секреты и не попадать в Git.

Для Render используется переменная `DATABASE_URL`:

```text
postgres://user:password@host:5432/database
```

`Program.cs` преобразует её в строку подключения Npgsql. Для внутреннего
PostgreSQL Render используется `SSL Mode=Disable`, для внешнего адреса —
TLS. Режим можно переопределить переменной `DATABASE_SSL_MODE`.

## API

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/` | Проверка приложения |
| GET | `/api/info` | Информация о приложении и БД |
| GET | `/api/cargoes` | Список, поиск, фильтрация и сортировка |
| GET | `/api/cargoes/{id}` | Груз по идентификатору |
| GET | `/api/cargoes/search?search=...` | Поиск по названию, категории, описанию, поставщику |
| GET | `/api/cargoes/available` | LINQ: доступные грузы |
| GET | `/api/cargoes/heavy?minWeight=10` | LINQ: грузы тяжелее порога |
| GET | `/api/cargoes/stats` | LINQ: статистика по категориям |
| GET | `/api/cargoes/recent?days=30` | LINQ: грузы за последние N дней |
| POST | `/api/cargoes` | Создание |
| PUT | `/api/cargoes/{id}` | Изменение |
| DELETE | `/api/cargoes/{id}` | Удаление |

Query-параметры списка:

- `search` — поиск без учёта регистра через `EF.Functions.ILike`;
- `category` — фильтрация по категории;
- `available` — фильтрация по наличию;
- `minWeight`, `maxWeight` — фильтрация по весу;
- `sortBy` — `name`, `category`, `weight`, `quantity` или `id`.

Примеры LINQ-запросов:

```csharp
// Фильтрация
var heavy = await db.Cargoes
    .Where(cargo => cargo.Weight > 10)
    .ToListAsync();

// Сортировка
var byWeight = await db.Cargoes
    .OrderBy(cargo => cargo.Weight)
    .ToListAsync();

// Условие + сортировка
var available = await db.Cargoes
    .Where(cargo => cargo.IsAvailable)
    .OrderBy(cargo => cargo.Name)
    .ToListAsync();

// Группировка и агрегаты
var stats = await db.Cargoes
    .GroupBy(cargo => cargo.Category)
    .Select(group => new
    {
        Category = group.Key,
        Count = group.Count(),
        TotalWeight = group.Sum(cargo => cargo.Weight * cargo.Quantity)
    })
    .ToListAsync();
```

## Публикация на Render

1. Создать PostgreSQL: **New → PostgreSQL**, имя `wt-lab7-db-yushkevich`.
2. Создать **Web Service** из GitHub-репозитория WT-7.
3. Указать Runtime: **Docker**, Dockerfile Path: `./Dockerfile`.
4. В **Environment** добавить `DATABASE_URL` = **Internal Database URL**
   созданной базы PostgreSQL.
5. Выполнить Deploy.
6. Проверить `GET /api/info`, `GET /api/cargoes`, `GET /api/cargoes/1`.
7. Убедиться, что в логах есть подключение к PostgreSQL, проверка и применение
   миграций, запуск HTTP API.

Альтернативно можно использовать Blueprint [`render.yaml`](render.yaml):
он создаёт PostgreSQL и Web Service и автоматически передаёт строку подключения
через `fromDatabase`.

При каждом `git push` Render выполняет новый deploy. При старте приложения
`Database.Migrate()` автоматически применяет новые миграции, поэтому структура
PostgreSQL обновляется без ручного SQL.
